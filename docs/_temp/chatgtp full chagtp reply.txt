```text
      ↓

      ├── NO → keep operating
      └── YES
            ↓
       Sync event
            ↓
       Supabase
            ↓
       ACK received
            ↓
       Mark event synced
```

That is much safer than:


### 2. Give every business record a permanent UUID

Never depend on SQLite's integer IDs matching PostgreSQL IDs.

For example:

```text

party.id = UUID
material.id = UUID
```

The same UUID exists locally and in Supabase.

```text

Supabase:
sale.id = 8f3...
```

No ID translation table should be necessary for normal entities.

Every mutation creates an outbox record in the **same SQLite transaction**.

Conceptually:

```text

INSERT outbox_event

COMMIT
```

```text
Sale exists

```

The outbox might contain:

```text

created_at
attempt_count

```

```text

event ABC
event ABC
event ABC
event ABC
```

Supabase must effectively say:

> Already processed ABC. Ignore the duplicates.

Not:

> Create five sales.

This means every event needs a globally unique `event_id`, and the server needs to enforce uniqueness.

```text
Sync immediately if online
```
